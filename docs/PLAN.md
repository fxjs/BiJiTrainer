# 比鸡配牌训练 H5：规划

目标：训练六人比鸡的最佳摆牌，减少实战中的配错。核心是规则引擎与求解器，UI 是输入与展示层。
后续还会开发对战游戏（本期不做），因此规则引擎、求解器、音效都做成可复用的独立包。

规则与策略的依据是 [ThinkBiJi](../../ThinkBiJi) 的讲义 `docs/liuren-biji.html` 与模拟 `sim/biji_sim.py`；
本仓库的规则引擎与该 Python 实现逐项对拍。

## 1. 规则口径

| 项目 | 口径 |
|---|---|
| 人数与发牌 | 6 人，54 张（含大小王）全部发完，每人 9 张，无底牌 |
| 摆牌 | 头、中、尾各 3 张，须 尾道 ≥ 中道 ≥ 头道，否则为倒水 |
| 牌型 | 三条 > 同花顺 > 同花 > 顺子 > 对子 > 乌龙 |
| 顺子 | QKA 最大，A23 最小（A23 的主牌是 3） |
| 大小王 | 配色不配点：大王只补 ♥♦，小王只补 ♠♣，只能用于凑同花；双王不能同在一个同花；比点时王小于 2，大王大于小王 |
| 花色 | ♠ > ♥ > ♣ > ♦，无平局。对子比对子中较大的花色，其余牌型比点数最大一张的花色 |
| 名次分 | 每道 6 人排名：第一名收 15 分，第 2~6 名依次付 1~5 分 |
| 喜牌 | 通关、双顺清、四个头、双豹子、全红、全黑、同花连顺，及更强的同类三顺清、全三条。每个喜其余每名未弃牌者付 5 分；多个喜叠加，同类只计较强者（三顺清不另计双顺清，全三条不另计双豹子）。每组四个头各计一喜：两组四个头 + 摆成双豹子 = 3 喜，再通关 = 4 喜 |
| 弃牌 | 看牌后、亮牌前按座次依次声明，后声明者能看到前面谁已弃牌。第 1 个弃牌者放 15 分到台面，之后依次为 12、9、6、3；台面分三等分，由三道各自的第一名拿走。此后本局与弃牌者无关：不收喜、不付喜。第一个弃牌者下一局做首家（花分买主动权） |
| 倒水 | 倒水者在每一道都排在所有未倒水的摆牌者之后；多人倒水时彼此按该道实际强度排序。不计依赖摆法的喜（双豹子、双顺清等），只看牌构成的喜（四个头、全红等）照常计 |

### 1.1 结算的等价形式

第 k 个弃牌者放 3 × (6 − k) 分，三道各拿走 6 − k 分，等价于他在三道都排第 7 − k 名并照常付名次分。
因此无论几人弃牌，每道第一名收到的总数恒为 15 分：例如 1 人弃牌时，其余 4 名摆牌者付 1+2+3+4 = 10，加台面 5。
`core` 的结算按这一等价形式实现（弃牌者排在所有摆牌者之后，第 1 个弃牌者垫底）。

## 2. "最优"的定义

目标是"期望得分最多"，标准差只作为信息展示，不参与推荐排序：

- **期望得分 EV**：三道名次分 + 通关 + 自己能成的喜 + 因为自己的摆法挡住或放行对手通关而变化的付分。
- **稳定性 σ**：同一手牌、同一摆法在对手随机分布下得分的标准差，显示在结果页供参考。
- **等价最优**：与平均得分最高者之差 ≤ max(ε, 2 × 配对标准误) 的摆法都判为最优，ε = 0.5 分。所有候选共用同一批对手牌，差值的配对标准误远小于各自均值的标准误。
- **推荐摆法**：平均得分最高者；平均得分相同时取 σ 较小者。推荐摆法的平均得分不会低于玩家自己的摆法或任何精排候选。
- 结果页同时展示 EV 与 σ，让玩家看到不同候选的期望与波动。

## 3. 求解器

合法摆法最多 1680 种，穷举开销可以忽略，难点在估值。

| 层 | 执行位置 | 方法 |
|---|---|---|
| 离线胜率表 | 构建期脚本 | 按讲义方法自博弈迭代（2 万 → 5 万 → 40 万局），得到每道的单挑胜率 p 与拿第一概率 T。每道估值 15T − 5(1−p)，通关按 25·T尾·T中·T头 近似 |
| 在线粗排 | Web Worker | 查表评估全部合法摆法，取前 K 名（约 10 个） |
| 在线精排 | Web Worker | 把实际剩余的 45 张随机发给 5 名对手（阻断效应在此计入），对手按查表策略摆牌，再按真实名次、通关、喜牌结算。约 2000 次采样，所有候选共用同一批采样以减小比较误差，输出 EV、σ、置信区间 |
| 弃牌决策 | Web Worker | 比较"最优摆法的 U"与"当前弃牌成本 −3×(6−k)"。前面已有人弃牌时，弃牌者的牌不参与比牌，按剩余摆牌人数采样；弃牌者的手牌分布偏弱，采样时按对手弃牌策略做条件筛选。后面座次是否弃牌未知，同样按对手策略模型估计。下一局首家的价值暂不量化，只作为提示展示 |

## 4. 训练功能

1. **自由练习（MVP）**：发 9 张 → 摆牌 → 提交 → 判定。允许提交倒水摆法并按倒水结算。结果页：玩家摆法与推荐摆法对照、每道拿第一的概率、EV 损失、σ、在全部合法摆法中的排名。
2. **错因标签**：规则判定，不依赖 LLM。
   - 漏喜：能成双豹子或双顺清却没有摆成
   - 倒水
   - 有喜仍弃牌（弃牌即放弃所有喜分）
   - 顺子错放在中道
   - 该拆的三条没拆 / 不该拆的拆了
   - 王落进乌龙，或王没有顶替同花里最不重要的那张
   - 三道平均用力，没有集中争两道
   - 天然同花没有留给要争的那一道
3. **弃牌训练**：在座次与前面已弃牌人数不同的情境下，判断该不该弃。
4. **错题本**：按间隔重复安排重练；重练时对花色做等价置换，防止记牌面。
5. **专项题库**：收录讲义牌例；离线从大量随机手牌中筛出"直觉摆法与最优摆法 EV 相差 ≥ 10 分"的牌例，按错因分类。
6. **限时模式、统计面板**：最优率、平均 EV 损失、各错因占比的趋势。

## 5. 音效

| 事件 | 音效 | 说明 |
|---|---|---|
| 发牌 | 轻洗牌声 + 9 次连续短促的发牌声 | 音频时钟调度，无常驻渲染循环 |
| 选牌 / 放入某道 / 撤回 | 轻触 / 落牌 / 滑回 | 高频操作，音量低、时长 < 150 ms |
| 三道摆满 | 提示音；倒水时换成警示音并高亮违规的那一道 | |
| 提交判定 | 最优 / 次优 / 失误 / 倒水各一种 | 失误音不要刺耳 |
| 成喜 / 通关 | 较长的奖励音效 | 低频事件 |
| 限时最后 5 秒 | 每秒滴答 | 仅限时模式 |
| 连续最优 | 连击音，音高逐级升高 | |

实现：
- Web Audio API，全局一个 AudioContext；首次指针或键盘手势解锁。纸面瞬态与提示音按需生成 PCM 后缓存，播放时只创建一次性播放节点；不下载音频文件。
- 短起音、指数衰减、尾部归零与总线压缩限制叠音峰值。选牌与取消音色不同，滑选反馈合并到至少 25 ms 间隔；最多 12 个同时播放节点。静音、切后台及下一手取消未播放的声音，静音与后台挂起音频设备。
- 设置：总开关、音量、震动。震动用 `navigator.vibrate`，仅 Android 生效，iOS Safari 不支持。

## 6. 仓库结构

pnpm workspace。`core`、`solver`、`audio` 为纯 TS、不依赖 DOM（`audio` 除外），供后续对战游戏的服务端结算与 AI 对手复用。

```
packages/core     规则引擎：牌编码、牌型强度、摆法与倒水、喜牌、结算     ← M0 已实现
packages/solver   摆法估值、蒙特卡洛精排、错因诊断、弃牌判断   ← M1、M3 已实现
packages/audio    音效管理                                           ← M2 已实现
scripts/          胜率表生成、专项题库筛选、与 Python 对拍
apps/trainer      训练 H5（Vite + Vue 3 + TS + Pinia + UnoCSS，Supabase Auth 与云端存储）
supabase/         数据库迁移、账号隔离 RLS、事务 RPC、本地开发配置与数据库行为测试
apps/battle       对战游戏（后续，本期不建）
```

牌编码与强度编码沿用 `biji_sim.py`（0..51 普通牌，52 小王，53 大王；强度整数可直接比较），
以便胜率表、牌例可在两边互相校验。

### 7.2 M2 实现说明

- 交互：点选手牌（可多选；横向滑过多张可连续选中/取消）→ 点某一道放入，放不下的牌保持选中；点道内的牌撤回。每道右侧的 ↑↓ 可把整道牌与相邻道互换，倒水时无需逐张撤回。手牌区可按花色或按点数排序（默认按花色，对应讲义"先按花色分组"）。已摆满的相邻道实时检查倒水；尾道与头道都满且尾道更小时提前提示。
- 提交后在 Web Worker 中运行 `recommend`（2000 局，约 1 秒），胜率表只打包进 Worker。结果页：评级、你的摆法与推荐摆法（平均得分、σ、各道拿第一概率、通关概率、表估值排名）、其他 3 个候选；可"重摆这一手"或"下一手"。
- 评级：最优（抽样误差内与最优无法区分）/ 次优（平均得分差 < 3 分）/ 明显失误（≥ 3 分）/ 倒水。
- 设置：音效开关、音量、震动保存在当前浏览器的 localStorage。会话统计只在内存中；练习记录与错题本按人物 UUID 保存在 Supabase，不读取或迁移旧的本机历史。
- 音效：发牌、选牌、取消、落牌、撤回、摆满、倒水警示、提交、四档评级（最优随连击升调）、成喜及轻量导航反馈；限时滴答预留。设置中可试听落牌与最优反馈。
- 验证：摆牌状态逻辑与评级有回归测试；Vue 类型检查与生产构建通过，浏览器交互及数据验证见 7.4。

### 7.3 M3 实现说明

**错因标签**（`solver/diagnose.ts`）：只在评级不是最优时诊断，所有判定都对照推荐摆法。

| 编码 | 名称 | 判定 |
|---|---|---|
| foul | 倒水 | 玩家摆法倒水 |
| missedXi | 漏喜 | 全部合法摆法能达到的双豹子 / 双顺清等喜数 > 玩家摆法 |
| greedyTail | 尾道优先的直觉摆法 | 玩家摆法 = 字典序（尾、中、头）最大的摆法，且不是推荐摆法 |
| keptTrips / splitTrips | 该拆的三条没拆 / 不该拆的拆了 | 同一点数的三条，玩家与推荐摆法一个保留一个拆开 |
| jokerMisuse | 王的用法 | 推荐摆法中王在同花里，玩家摆法中不在 |
| straightInMiddle | 顺子错放在中道 | 玩家中道为顺子且拿第一 < 5%，推荐摆法头道为顺子 |
| notConcentrated | 没有集中火力 | 推荐摆法有 ≥ 2 道拿第一 ≥ 70% 且放弃一道（≤ 5%），玩家把握较大的道更少 |
| headWasted | 头道本可以争第一 | 推荐摆法头道拿第一 ≥ 40%，玩家 < 10% |
| other | 其他 | 以上都未命中，给出各道拿第一概率的对比 |

讲义 5 组"直觉摆法 vs 进阶摆法"全部命中预期标签（见 `diagnose.test.ts`）。

**错题本**：评为明显失误或倒水的手牌自动加入（同一手牌合并）。Leitner 盒子，间隔 0、1、3、7、16、35 天；复习评为最优进下一盒，次优 1 天后再练，失误或倒水退回第 0 盒；最优 6 次后移出。复习时随机做同色花色置换（♠↔♣、♥↔♦），保持大小王的配色关系。看过答案后"重摆这一手"不计入记录、错题本与统计。

**统计**：累计手数、最优率、平均损失、最近 50 手最优率、评级分布、错因排行、每 20 手一组的趋势。

**持久化**：Supabase 的 `training_records`、`training_mistakes` 按 `character_id` 隔离，匿名认证会话只允许访问当前绑定人物。知道已用名号即可恢复该身份，因此名号是弱凭证，不具备密码级保护。一手练习及其错题变更在同一事务保存；失败时保留当前结果并显式重试，不退回 IndexedDB 或内存并声称保存成功。

**弃牌判断**（`solver/fold.ts`）已实现，界面暂缓，原因如下。

#### 本桌规则下弃牌在得分上被"不弃"压制

前面已有 f 人弃牌时，自己弃牌付 3 × (5 − f)。不弃时场上最多 6 − f 人摆牌，每道最差排最后、付 5 − f，三道合计同样是 3 × (5 − f)；后面座次再有人弃牌只会更好。因此不弃的名次分最坏情况恰好等于弃牌成本（`settle.test.ts` 中有对应的性质测试）。

弃牌能多得的只有：
1. 免付他人的喜分，模拟中每手平均不到 1 分；
2. 第一个弃牌者下一局做首家。

蒙特卡洛也印证了这一点：弱牌在各座次下"不弃"的平均得分都高于弃牌成本，随机生成的 40 道弃牌题答案全部是"不弃"。

**待确认**：首家的价值值多少分？给出一个估计值（或一个可调参数）后，弃牌题才有非平凡的答案。

对手弃牌的启发式（`OPPONENT_FOLD_SLACK = 3`）也需要按实际牌桌经验校准。

### 7.4 名号身份、界面与触感音效升级

- 名号：登录页只有人物名输入、骰子与进入按钮，无注册、邮箱、密码或验证邮件。首次进入即创建人物身份；输入尚未隐退的已用原名号即可找回同一记录。后台初始 100 个唯一人物名，10 分钟候选保留防止并发撞名；掷骰不消耗名号，首次进入才占用，切换不删除记录也不会返还。“隐退江湖（删除）”经不可恢复的二次确认后删除全部对局与错题、退出所有设备，并以新 UUID 返还同名，允许他人重新选取。名字池用完仍可恢复未隐退身份，不在前端虚构替代名字。
- 云端：Supabase 匿名用户只作为会话传输认证，以人物 UUID 保存数据；未隐退的已用名号和训练记录不随匿名用户删除而丢失。所有受控 RPC 核对当前人物成员关系，稳定重试键避免重复计数或复习进度回退。隐退事务原子删除全部数据与成员关系并轮换 UUID，旧绑定与延迟请求无法跨到重新领取的同名人物；失败完整回滚。知道未隐退名号即可以恢复当前人物，不能将其当作敏感数据认证。迁移与匿名登录配置见 README，Pages 工作流不自动执行远程迁移。
- 界面：账号、牌桌、结果、错题本、统计及设置统一为深色牌桌主题。保留原生表单、键盘操作和可见焦点；设置使用原生模态 dialog，支持 Escape 和返回触发按钮的焦点恢复。
- 动效与布局：采用短时 transform / opacity 合成，不引入 PixiJS、不创建持续 JS 渲染循环；尊重减少动态效果设置。顶部导航与右侧按钮统一为 44px 高；竖屏牌桌铺满可用高度，手牌与操作区靠下。横屏三道并排，手牌靠左下，右下操作按钮排成两行；手牌首行完整显示 9 张，窄屏按宽度缩小且高度至少 44px，摆满或倒水时也保留底部操作空间。右上角支持横屏全屏及退出，方向锁定受浏览器能力约束。
- 大错题本：数据读取跨越 Supabase 单次 1000 行限制；界面每页最多渲染 20 手，保留全部到期计数和下一手复习规则。
